## 📖 Теория карточками

### 🃏 Декоратор: упаковка для функции
Декоратор принимает функцию и возвращает другую, «упакованную»: с замером времени, логом, кэшем. Саму функцию переписывать не нужно.

```python
@timer
def work(): ...


# то же самое, что: work = timer(work)
```

Декоратор срабатывает **один раз**, когда определяется функция, а упаковка работает при каждом вызове.

### 🃏 Контекстный менеджер: «открыл — закрыл»
Конструкция `with` сама делает уборку: например, замеряет время блока и останавливает секундомер, даже если внутри произошла ошибка.

```python
with Timer() as t:
    сделать_работу()
print(t.elapsed)
```

### 🃏 Генератор и `yield`: ленивая лента
Обычная функция возвращает весь результат сразу. Генератор отдаёт значения **по одному**, когда их просят. Миллиард значений не нужно хранить: берёте столько, сколько нужно.

### 🃏 Кэш, `bisect`, `heapq`
- `lru_cache` запоминает результаты функции: повторный вызов с теми же аргументами мгновенный.
- `bisect` ищет место в **отсортированном** списке бинарным поиском (вы писали его в модуле 1).
- `heapq` держит «кучу»: быстро достаёт наименьшие элементы без полной сортировки.

**Задание 5 🧠. «Сначала измерь, потом оптимизируй».** Две функции: `count_in_range` (сколько чисел отсортированного списка лежит в отрезке) и `k_smallest` (k наименьших чисел).

Порядок работы (это и есть инженерный подход):
1. Напишите **простое** решение: цикл по списку и `sorted(items)[:k]`.
2. Замерьте его с помощью вашего `Timer` на списке из миллиона чисел.
3. Только потом ускорьте: `bisect` и `heapq`. Замерьте снова и сравните.

Тесты проверят не секундомер, а **число операций**: обращений к списку и сравнений. Так результат не зависит от скорости вашего компьютера.

<details><summary>💡 Подсказка 1</summary>`count_in_range`: список отсортирован. Значит, границы отрезка можно найти бинарным поиском, а числа между ними просто посчитать вычитанием.</details>
<details><summary>💡💡 Подсказка 2</summary>В модуле `bisect` есть `bisect_left` (первое место для числа) и `bisect_right` (место после последнего такого числа). Прочитайте их описание в документации.</details>
<details><summary>💡💡💡 Подсказка 3</summary>Ответ для отрезка: `bisect_right(values, high) - bisect_left(values, low)`. Для `k_smallest` есть готовая `heapq.nsmallest(k, items)`; для `k <= 0` верните `[]`.</details>

**Задание 6 🤝. «Объясни коллеге».** Коллега-новичок спрашивает: «Чем генератор отличается от обычной функции, которая возвращает список? Зачем он нужен?» Напишите ответ в 3–4 предложения в свой файл `my_notes.md`, как будто говорите вслух. Потом сверьтесь с образцом.

<details><summary>Образец ответа</summary>

«Обычная функция считает весь список сразу и возвращает его целиком: если там миллион чисел, они все лежат в памяти. Генератор отдаёт значения по одному, когда их просят, и запоминает, где остановился. Поэтому он экономит память и подходит, когда нужны только первые несколько значений или поток данных без конца. Пример: можно взять три первых значения большого дерева, не обходя остальные».

**Критерии хорошего объяснения:**
1. Нет жаргона, а если он есть, расшифрован («лениво» = «по мере необходимости»).
2. Есть **образ или пример** (дерево, лента, очередь).
3. Названа **причина** («экономит память»), а не только определение.
4. Звучит как разговор, а не как цитата из документации.
5. Умещается в полминуты речи.

</details>

**Задание 7. Предскажи вывод (без запуска).** Что напечатает программа?

```python
def shout(func):
    print("декорирую")

    def wrapper():
        print("до")
        func()
        print("после")

    return wrapper


@shout
def hello():
    print("привет")


hello()
hello()
```

<details><summary>Ответ</summary>

```
декорирую
до
привет
после
до
привет
после
```

## 💡 А знаете?

Генераторы и слово `yield` появились в Python 2.2, в 2001 году, по предложению PEP 255. Среди его авторов Тим Петерс, тот самый, который потом написал алгоритм сортировки Timsort.
Подробнее: [PEP 255 — Simple Generators](https://peps.python.org/pep-0255/), [модуль functools](https://docs.python.org/3/library/functools.html).
