## Что это и зачем

Работающий код — это только начало. Его будут читать коллеги и вы сами через полгода.
Здесь мы научимся делать код понятным: меньше повторов, меньше лишних условий, больше подсказок для читателя.

## 📖 Теория карточками

### 🃏 DRY и KISS: две короткие привычки
**DRY** («не повторяйся»): одно и то же правило должно жить в одном месте. **KISS** («сделай проще»): не усложняйте без причины.
Признаки беды: копипаста с мелкими отличиями, лесенка из `if … elif … elif`. Лекарство: таблица данных вместо кучи условий.

### 🃏 `@dataclass`: класс без рутины
Если класс нужен только чтобы хранить данные, `@dataclass` сам напишет `__init__`, `__repr__` и сравнение.

```python
@dataclass
class Point:
    x: int
    y: int = 0
```

### 🃏 `@property`: поле с умом
Свойство выглядит как обычное поле, но за ним стоит функция: проверка значения или вычисление. Снаружи `t.celsius = 20`, а внутри сработает проверка.

### 🃏 Три классические ловушки Python
- **Изменяемое значение по умолчанию** (`def f(x, a=[])`): список создаётся один раз и копит данные между вызовами.
- **Размножение ссылки** (`[[0] * 3] * 2`): строки таблицы — один и тот же список.
- **Пустой ввод**: деление на `len([])` даёт `ZeroDivisionError`.

**Задание 7 🤝. Код-ревью.** Коллега прислал функцию. Напишите 3–4 комментария ревью в свой файл `my_notes.md`, как будто пишете их в Pull Request. Потом сверьтесь с образцом.

```python
def calc(l):
    r = []
    for i in range(len(l)):
        if l[i] % 2 == 0:
            r.append(l[i] * 2)
    return r
```

<details><summary>Образец ответа</summary>

1. **Название** (мелочь): «Мне трудно читать имя `l`: оно похоже на цифру 1. Предлагаю `numbers`. А `calc` не говорит, что именно считается. Может, `double_evens`?»
2. **Читаемость** (предложение): «Вместо `range(len(l))` можно перебирать сами числа, так нет риска ошибиться с индексом и короче. Например: `[n * 2 for n in numbers if n % 2 == 0]`».
3. **Соглашения проекта** (желательно до слияния): «Давайте добавим type hints и docstring, как в остальном модуле: `def double_evens(numbers: list[int]) -> list[int]:`».
4. **Плюс**: «Логика верная, и для пустого списка вернётся пустой список, это я проверил».

**Критерии хорошего ревью:**
1. **Вежливо**, без «ты написал плохо»: «мне трудно», «предлагаю», «а что, если».
2. **Конкретно**: названа строка или показан пример кода.
3. **С причиной**: понятно, зачем менять («похоже на 1», «риск ошибки»).
4. **С предложением решения**, а не только с критикой.
5. **С приоритетом**: ясно, что обязательно (блокер), а что пожелание (nit).
6. Есть **хотя бы одно положительное замечание**.

</details>

**Задание 8. Предскажи вывод (без запуска).** Что напечатает программа?

```python
def add(x, acc=[]):
    acc.append(x)
    return acc


print(add(1))
print(add(2))
print(add(3, []))
```

<details><summary>Ответ</summary>

```
[1]
[1, 2]
[3]
```

Список по умолчанию создаётся **один раз** при определении функции, поэтому второй вызов видит «1» из первого. Когда третьим аргументом передали свежий список, всё сработало как ожидалось.

</details>

## 💡 А знаете?

Декоратор `@dataclass` появился в Python 3.7. Предложение PEP 557 написал Эрик Смит в 2017 году, чтобы не писать одни и те же `__init__` и `__repr__` в сотнях классов.
Подробнее: [PEP 557 — Data Classes](https://peps.python.org/pep-0557/), [документация dataclasses](https://docs.python.org/3/library/dataclasses.html).
